01 / Motivation & Context

Why Quick Commerce Demands Cloud Computing

Quick commerce platforms (Blinkit, Zepto, Instamart) cannot survive on traditional monolithic architectures due to extreme real-time constraints.

⚡

Flash Demand Spikes

Traffic surges 10x–50x during meal times and monsoon showers. Rigid on-premise servers either crash under load or waste massive idle capital.

⏱️

Sub-100ms Inventory Locking

Dark stores carry finite local inventory. Over-selling creates costly delivery cancellations, requiring high-throughput, ACID-compliant database locking.

📦

Decoupled Media & Compute

Serving high-resolution grocery imagery directly from backend application servers quickly starves thread pools. Offloading media to Cloud Object Storage is essential.

KEY INSIGHT: Cloud computing allows quick commerce apps to decouple compute (EC2), object storage (S3), and transaction state (RDS) into distinct, independently scalable tiers.

04 / Fulfillment Engine

10-Minute Asynchronous Order State Machine

In quick commerce, the checkout HTTP request cannot block while dark store operations occur. MinutDel implements an asynchronous state machine:

1

PLACED (T + 0s)

ETA: 10 mins

Transaction written to DB, stock quantities decremented, simulation thread spawned via @Async.

2

PACKING (T + 5s)

ETA: 8 mins

Simulates Dark Store #07 picker assembling grocery items from micro-warehouse shelves.

3

RIDER_ASSIGNED (T + 11s)

ETA: 6 mins

Delivery partner allocated (e.g. Amit Sharma • +91 98711-22334), ready for package handoff.

4

OUT_FOR_DELIVERY → DELIVERED (T + 17s → T + 25s)

10 MIN GUARANTEE MET

Last-mile dispatch simulation completed; real-time polling reflects instantaneous delivery completion.

05 / Backend Architecture

Spring Boot 3 & Dual-Profile Database Agility

Designed for zero-lock-in: write once, test locally with zero dependencies, deploy directly to AWS.

Local Profile (local)

ZERO SETUP
  • ✓ Embedded H2 Database: Spins up automatically in RAM. No local PostgreSQL or Docker install required.
  • ✓ Automatic Seeding: DataLoader.java seeds 12 groceries + 5 categories on startup.
  • ✓ H2 Web Console: Live table inspections at /h2-console.

Production Profile (aws)

CLOUD MANAGED
  • ✓ Amazon RDS PostgreSQL: Activated via --spring.profiles.active=aws.
  • ✓ Spring Data JPA Abstraction: Zero code changes to entities or queries between H2 and RDS.
  • ✓ AWS SDK v2 S3 Integration: Transparently resolves image URLs from S3 buckets with fallback.
// Switching database requires changing only the JDBC connection URL:
spring.datasource.url = ${RDS_JDBC_URL:jdbc:postgresql://your-rds-endpoint.amazonaws.com:5432/minutdeldb}

07 / Security & Networking

AWS Security, Networking & 12-Factor Compliance

Production-grade cloud security and architecture guidelines demonstrated in this implementation.

🛡️ Security Groups (Virtual Firewall)

Strict least-privilege ingress rules enforced at the AWS VPC edge:

Port 22 (SSH) Restricted Admin Access
Port 80 (HTTP) Public Inbound Web Traffic
Port 8080 (Custom TCP) MinutDel Full-Stack App

📐 12-Factor Cloud Principles

1. Stateless Compute: EC2 instances store no persistent data. Sessions & transactions live in RDS / external storage.
2. Externalized Config: Secrets, database credentials, and bucket names injected via environment variables.
3. Port Binding: Self-contained HTTP listener (Tomcat embedded) exported on port 8080.
08 / DevOps & CI/CD

Zero-Friction Cloud Deployment Workflow

How MinutDel transitions from local developer workstation to 24/7 public cloud execution in 3 steps:

01

Code & Version Control

Clean Git repository with rigorous .gitignore rules. Pushed to remote GitHub repository:

github.com/ArnavAstu/MinutDel
02

EC2 Cloud Provisioning

Launch Ubuntu 24.04 instance. Pull code directly via Git, compile unified JAR artifact with Maven:

mvn clean package -DskipTests
03

Daemon Execution

Launch background daemon on EC2. Instantly accessible from any browser globally:

http://<EC2-PUBLIC-IP>:8080
🐳 Docker Ready: Multi-stage Dockerfile included to build minimal Alpine-based containers if orchestrating via Amazon ECS or Kubernetes.
